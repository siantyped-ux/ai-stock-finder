# 백테스트 하네스 설계 (2단계)

작성일: 2026-08-18
상태: 승인됨

## 배경

0단계에서 `history/<KST날짜>.csv` 아카이브를, 1단계에서 `exit_rules.py` 청산 규칙을
만들었다. 이 둘을 결합해 "시그널대로 매매했다면 어떤 트레이드가 나왔는가"를
재현하는 것이 2단계다.

이 하네스 없이는 3단계(EV 재캘리브레이션)를 할 수 없다. 스코어를 실현수익과
맞추려면 먼저 "그 스코어로 진입해 규칙대로 청산했을 때의 실현수익"이 정의돼야
하는데, 그 정의가 곧 이 하네스다.

## 지금 이 하네스로 알 수 있는 것과 없는 것

아카이브를 조회한 결과, 현재 데이터로는 **시그널 성능을 판단할 수 없다.**

| 사실 | 함의 |
|---|---|
| 아카이브 18일, 보유 상한 60거래일 | 보유 만료(TIME)로 끝나는 트레이드는 **0건**이다. 손절·트레일·시그널 청산은 18일 안에도 일어날 수 있으나, 표본이 추세 초반에만 치우친다 |
| 진입 후보 32건이 전부 `source=backfill` | 스코어가 미확정 봉 결함에 오염돼 있다 |
| 진입 후보 32건이 전부 미국 종목, 고유 7개 | 표본이 없다시피 하다 |

따라서 지금 이 하네스의 용도는 **파이프라인 정합성 검증**이다. 조인이 맞는지,
비용이 반영되는지, 룩어헤드가 없는지, 미결 포지션이 통계에 섞이지 않는지를
확인한다. 시그널 판단은 `source=live` 데이터가 최소 한 번의 보유기간을 채운
뒤에 시작한다.

## 목표

1. 아카이브의 시그널과 `exit_rules` 를 결합해 트레이드 목록을 재현한다.
2. 성과를 R 배수로 집계한다 — 자본도 환율도 필요 없다.
3. 오염된 데이터로 낸 결과를 성능 근거로 오독할 수 없게 만든다.

## 비목표 (의도적 제외)

- **포지션 사이징·Kelly** — 3단계. `ev` 가 캘리브레이션되기 전에는 근거가 없다.
- **자산곡선·Sharpe·MDD** — 사이징이 정해져야 계산된다. 3단계 이후.
- **워크포워드·파라미터 최적화** — 3단계. 지금 맞추면 18일에 과최적화하는 것이다.
- **공매도** — 스캐너가 매수 시그널만 낸다.
- **상장폐지·거래정지 처리** — 현 유니버스에 해당 종목이 없다.

## 설계 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 집계 단위 | R 배수 | 사이징(3단계)이 없어도 성립하고, 한국·미국 종목을 같은 잣대로 비교한다. v5 의 EV 수식도 R 단위라 그대로 연결된다 |
| 진입 규칙 | BUY 로 **전환**될 때만 | FISV 가 12일 연속 BUY 로 나온다. "BUY 면 진입"은 같은 종목에 매일 새 포지션을 연다. 전환 기준이면 손절 후 시그널이 BUY 로 남아 있어도 재진입하지 않아, 방금 털린 종목을 다음날 다시 사는 일이 없다 |
| 거래비용 | 시장별 분리 | 한국은 매도에만 거래세가 붙고 미국은 없다. 하나로 묶으면 한쪽이 체계적으로 왜곡된다 |
| 시뮬레이션 구조 | 티커별 독립 루프 | 사이징·노출한도가 없어 트레이드가 서로 독립이다. 종목 하나를 순수 함수로 돌리면 테스트가 단순해진다 |

### 검토했으나 채택하지 않은 대안

- **원화 포트폴리오 자산곡선**: Sharpe·MDD 를 바로 낼 수 있으나, 사이징 규칙을
  지금 임의로 정해야 한다. 그것은 3단계의 결론을 선취하는 것이고, 임의 가정이
  MDD 를 좌우해 결과 해석을 오도한다.
- **재진입 쿨다운(청산 후 N일 금지)**: 반복 손절을 직접 막지만 파라미터가 하나
  늘고, 튜닝할 데이터가 없는 지금 N 을 임의로 정해야 한다. 전환 기준이 같은
  효과를 파라미터 없이 낸다.
- **날짜별 전체 시장 루프**: 포트폴리오 제약이 있을 때 필요한 구조인데 지금은
  그 제약이 없다. 복잡도만 늘어난다.
- **pandas 벡터화**: 트레이드 32건 규모에 조기 최적화다. 디버깅도 어려워진다.

## 모듈 구조

```

tests/test_trade_sim.py    신규
```

`trade_sim.py` 는 파일도 네트워크도 건드리지 않는다. `backtest.py` 가 아카이브를
읽고 OHLC 를 받아 넘긴다. `history.py`·`exit_rules.py` 와 같은 패턴이다.

`trade_sim.py` 는 `exit_rules` 만 임포트한다. `history.py`·`stock_finder.py` 는
임포트하지 않는다.

## 데이터 모델

```python
@dataclass(frozen=True)
class Costs:
    """편도 비용률(%). 전부 진입가 대비 백분율이다."""
    us_buy_pct: float = 0.10
    us_sell_pct: float = 0.10
    kr_buy_pct: float = 0.02
    kr_sell_pct: float = 0.02
    kr_tax_pct: float = 0.15       # 매도 시 거래세 (아래 주석 참조)
    slippage_pct: float = 0.05     # 편도


@dataclass(frozen=True)
class Trade:
    ticker: str
    market: str                    # "US" | "KR"
    source: str                    # "live" | "backfill"
    entry_date: str
    entry_price: float
    r_unit: float
    exit_date: Optional[str]       # 미결이면 None
    exit_price: Optional[float]
    exit_reason: Optional[str]     # TIME | SIGNAL | STOP | TRAIL
    bars_held: int
    is_open: bool
    gross_r: float
    cost_r: float
    net_r: float
```

### 한국 거래세율 주의

`kr_tax_pct` 기본값 0.15% 는 확정된 값이 아니다. 국내 증권거래세는 최근 몇 년간
단계적으로 인하돼 왔고, 2026년 시행 세율을 이 문서 작성 시점에 확인하지 못했다.
**현재 진입 후보에 한국 종목이 0건이라 결과에 영향이 없으나, 한국 트레이드가
발생하기 전에 반드시 실제 세율로 교체해야 한다.** 값이 코드에 하드코딩되지 않고
`Costs` 필드로 노출돼 있어 교체는 한 줄이다.

## 비용의 R 환산

각 side 를 실제로 지불되는 가격에 매긴다.

```
매수측 = 진입가 x (매수비용% + 슬리피지%) / 100
매도측 = 청산가 x (매도비용% + 거래세% + 슬리피지%) / 100
cost_r = (매수측 + 매도측) / r_unit
net_r  = gross_r - cost_r
```

`r_unit = stop_atr_mult x ATR` 이므로 변동성이 큰 종목은 R 이 커져 비용 부담이
자동으로 작아진다. 별도 보정이 필요 없다.

### 진입가 기준 근사를 쓰지 않는 이유

초안은 매도측도 진입가 기준으로 잡고 "손절폭이 진입가의 10% 안팎이라 오차가
0.01R 미만"이라고 적었다. **그 근거는 틀렸다.** 실측하면 오차는

```
오차R = (매도측 비용률%) x n / 100        (n = 실현 R 배수)
```

이고 손절폭과 무관하다. 손절폭 5%·9%·20% 어디서든 값이 같다. 오차 0.01R 을
넘기 시작하는 지점은 US 가 n=6.67R, KR 이 n=4.55R 이며, 방향은 항상 낙관적이다
(비용 과소계상).

추세추종은 소수의 큰 승리에서 수익이 나므로 정확히 그 구간에서 근사가 무너진다.
게다가 미결 포지션도 마지막 종가로 평가하므로 청산가는 언제나 있다 - 근사할
이유 자체가 없었다.


## 진입 규칙과 주말 처리

스캔은 **주말에도 매일** 돌지만 그날은 세션이 없다. 봉이 없는 날을 그냥
건너뛰면 **토요일에 처음 BUY 로 전환된 종목은 영영 진입하지 못한다** — 월요일에는
이미 전환이 아니기 때문이다.

```
아카이브 날짜를 순서대로 순회하며 was_buy 를 봉 유무와 무관하게 추적한다.

  not was_buy -> is_buy      : pending_entry = True
  pending_entry 이고 봉 있고 미보유 : 시가 진입, pending_entry = False
  is_buy 가 아니게 됨        : pending_entry = False
```

`is_buy` 는 `signal in ("BUY", "STRONG_BUY")` 이다.

`market` 은 아카이브의 `market` 열을 그대로 쓴다. 티커 접미사(`.KS`/`.KQ`)로
추론하지 않는다 — 스캐너가 이미 판별해 기록한 값이 있는데 다시 추론하면
두 판별이 어긋날 여지가 생긴다.

## 종목별 루프

```
봉 없음   : 아무것도 하지 않는다 (bars_held 증가 없음)
보유 중   : decision = evaluate(pos, bar, params)
            청산이면 Trade 확정, 아니면 pos = advance(pos, bar, params)
미보유    : pending_entry 이면 bar.open 에 진입
```

`exit_rules` 의 계약대로 **evaluate 먼저, advance 나중**이다.

진입 시 `atr_at_entry` 와 `Bar.atr14` 는 모두 **D-1 까지의 봉으로 계산한 ATR** 을
넘긴다. 당일 고저를 포함해 계산하면 개장 전에 정해져 있어야 할 손절선이 미래
정보를 쓰게 된다 — `exit_rules.Bar` docstring 이 명시한 타이밍 계약이다.

같은 날 청산과 재진입은 일어나지 않는다. 전환 기준이라 재진입하려면 시그널이
BUY 에서 이탈했다 복귀해야 하고, 그것은 최소 다음 날이다.

## 미결 포지션

아카이브 마지막 날까지 청산되지 않은 포지션은 **마지막 봉 종가로 평가**하되
`is_open=True` 로 표시한다.

**승률·평균 R·EV 는 닫힌 트레이드로만 계산한다.** 미결 포지션을 섞으면 아직
손절되지 않았을 뿐인 포지션이 승리로 잡혀 성과가 부풀려진다. 미결은 별도 표로만
낸다.

## 리포트

출력 순서가 중요하다. 데이터 출처를 가장 먼저 낸다.

```
[데이터 커버리지]
  아카이브 N일 (첫날 ~ 마지막날)
  source: backfill A / live B
  BUY 후보 X종목 중 Y종목 진입
  최신 봉 (날짜) · 전환 후 세션이 없어 대기 중: (티커들)
  !! backfill 스코어는 미확정 봉 결함에 오염된 값이다.
     이 결과는 파이프라인 검증용이며 시그널 성능의 근거가 아니다.

[닫힌 트레이드] n건 · 승률 · 평균 net R · EV/trade · 청산사유별 분해
[미결 포지션]   m건 · 평가 net R (닫힌 통계와 분리)
```

`source` 구성을 먼저 출력하는 이유는, 이 경고가 없으면 몇 달 뒤 결과만 보고
시그널이 검증됐다고 오독하기 때문이다. 0단계에서 확인했듯 `backfill` 행의
스코어는 그때 대시보드가 보여준 값이지 올바른 값이 아니다.

`live` 비율이 0 이면 경고를 출력한다. 100% 면 출력하지 않는다.

## 결측·예외 처리

| 상황 | 처리 |
|---|---|
| 아카이브 날짜에 해당하는 봉 없음 | 그날 건너뛴다. `bars_held` 증가 없음 |
| 티커의 OHLC 조회 실패 | 그 티커의 트레이드를 만들지 않고, 리포트에 실패 목록을 출력 |
| 진입 시점 ATR 이 None 또는 0 | 진입하지 않는다 (`exit_rules.open_position` 이 `ValueError` 를 던지므로 호출 전에 걸러낸다) |
| 아카이브 행의 `close` 가 빈 값 | 시그널만 쓰고 가격은 OHLC 재조회분을 쓴다 — 영향 없음 |

## 테스트

`trade_sim.py` 가 순수 함수이므로 합성 데이터로 전부 검증한다. 네트워크 불필요.

1. **진입 전환** — 연속 BUY 에서 첫날만 진입하는지
2. **주말 이월** — 봉 없는 날 전환된 pending 이 다음 세션에 진입되는지
3. **pending 해제** — 봉이 오기 전에 BUY 에서 이탈하면 진입하지 않는지
4. **보유 중 재진입 없음** — 보유 상태에서 BUY 가 계속돼도 새 포지션이 안 생기는지
5. **청산 후 재진입** — 이탈했다 복귀해야 다시 진입하는지
6. **비용 R 환산 (US)** — 수수료·슬리피지가 `net_r` 에 반영되는지
7. **비용 R 환산 (KR)** — 매도 거래세가 추가로 반영되는지
8. **미결 포지션 분리** — 승률·평균 R 집계에서 제외되는지
9. **미결 평가** — 마지막 봉 종가로 `gross_r` 이 계산되는지
10. **evaluate → advance 순서** — 오늘 고가가 오늘 청산 판정에 반영되지 않는지
11. **봉 없는 날** — `bars_held` 가 증가하지 않는지

## 완료 기준

- `trade_sim.py` 가 순수 함수로 구현되고 위 테스트 11건이 통과한다.
- `trade_sim.py` 가 `history.py`·`stock_finder.py` 를 임포트하지 않는다.
- `python backtest.py` 가 현재 아카이브로 오류 없이 실행되어, 데이터 커버리지
  경고와 닫힌 트레이드·미결 포지션을 각각 분리해 출력한다. 실제 건수는 실행해
  봐야 안다 — 시그널 이탈로 SIGNAL 청산되는 트레이드가 있을 수 있다.
- 리포트가 `source=backfill` 비중을 닫힌 트레이드 통계보다 먼저 출력한다.

# 가상매매 성과 누적 리포트 설계

작성일: 2026-08-19
상태: 검토 대기

## 배경

2단계에서 `backtest.py`가 아카이브 시그널을 트레이드로 재현하고 R 배수 통계를
콘솔에 출력하게 됐다. 그러나 R 배수는 리스크 정규화 단위여서 "얼마 벌었나"를
묻는 사람에게는 읽히지 않고, 콘솔 출력은 실행한 그 순간에만 존재한다.

매영업일 KST 10:00에 원화 손익이 적힌 XLSX를 자동 생성해 리포에 누적한다.

## 목표

1. 티커·진입일·진입가·청산일·청산가·수익금액·수익률을 XLSX로 낸다.
2. 손실은 반드시 `-` 부호로 표시한다.
3. 매영업일 자동 실행하고, 지난 리포트를 지우지 않는다.

## 비목표 (의도적 제외)

- **포지션 사이징·Kelly** — 3단계. 이 리포트의 정액 투자는 금액을 읽히게 만드는
  표시 장치일 뿐 전략이 아니다.
- **벤치마크 대비 성과(알파)** — 지수 데이터 조인이 필요하다. 표본이 쌓인 뒤.
- **차트·조건부서식 색상** — 숫자와 부호로 충분하다.
- **한국 증권거래세율 확정** — `trade_sim.Costs.kr_tax_pct` 의 미확정 경고를
  그대로 승계한다. 현재 한국 종목 진입 0건이라 결과에 영향이 없다.

## 지금 이 리포트로 알 수 있는 것과 없는 것

2단계 설계서의 경고가 그대로 유효하다. 2026-08-19 기준:

| 사실 | 함의 |
|---|---|
| 청산완료 1건 (YPF), 미결 6건 | 승률·평균수익률은 통계적으로 무의미하다 |
| 아카이브 19일 중 `live` 는 1일치(전체 행의 5%) | 진입 판단에 쓰인 스코어가 미확정 봉 결함에 오염돼 있다 |
| 보유 상한 60거래일 | 만기 청산 표본이 나오려면 2026년 11월 중순 |

**이 리포트의 현재 용도는 파이프라인 검증이다.** 요약 시트 최상단에 이 경고를
고정 배치해, 숫자만 보고 성능으로 오독할 수 없게 만든다.

## 설계 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 모듈 배치 | `perf_report.py` 신설 + `report.yml` 워크플로 분리 | 스캔(1,100종목)과 리포트(환율 1건+후보 7종목)는 실패 원인이 다르다. 묶으면 재실행 단위가 통째로 커진다 |
| 시뮬레이션 | `backtest.run()` 그대로 재사용 | 진입·청산 규칙을 두 벌 유지하지 않는다 |
| 금액 기준 | 종목당 원화 정액 1,000만원 | R 배수는 "얼마"에 답하지 않는다. 정액은 종목 간 비교를 가능하게 하는 최소 가정이다 |
| 환율 | 진입일·청산일 각각의 `USDKRW=X` 종가 | 실제 원화 손익에는 환차가 포함된다. 고정환율은 편해도 거짓이다 |
| 수량 | `floor(1,000만원 / 원화진입가)` | 실제 증권사 주문과 같다. 잔액은 미투자 |
| 비용 | 총수익·순수익 둘 다 컬럼으로 | 비용이 성과를 얼마나 갉는지가 보여야 3단계 EV 캘리브레이션에 쓸 수 있다 |
| 미결 포지션 | 별도 시트 | `summarize()` 가 이미 지키는 원칙이다. 섞으면 "아직 손절 안 된" 포지션이 승리로 잡힌다 |
| 산출물 | Actions artifact 로만 업로드 (보존 90일) | **저장소가 public 이다.** 손익 금액을 커밋하면 영구히 공개 이력에 남는다. 리포트는 `history/*.csv` 에서 언제든 재생성되므로 커밋해 보존할 이유가 없다 |

### 검증용 컬럼을 넣는 이유

요청받은 컬럼은 7개(티커·진입일·진입가·청산일·청산가·수익·수익률)다. 여기에
**수량·진입환율·청산환율·청산사유** 4개를 뒤쪽 블록으로 덧붙인다.

원화 손익은 `가격 × 수량 × 환율` 세 값의 곱이다. 셋 중 둘이 숨으면 "YPF
-636,000원"이 맞는지 아무도 검증할 수 없고, 환율 조회가 조용히 틀렸을 때
알아챌 방법이 없다. 요청 컬럼은 A~G열에 원래 순서대로 두고, 검증 컬럼은
H열 이후에 배치한다.

## 아키텍처

```
history/*.csv ──> backtest.run() ──> Trade[] ─┐
                                               ├─> build_rows() ──> write_xlsx()
yfinance USDKRW=X ──> fetch_fx() ──> {날짜:환율} ┘
```

### perf_report.py 의 단위

| 함수 | 책임 | 순수성 |
|---|---|---|
| `fetch_fx(start, end)` | `USDKRW=X` 일봉 종가를 `{날짜: 환율}` 로. 아카이브 최초일 −10일부터 오늘까지 받아, 첫 진입일이 휴일이어도 소급할 값이 있게 한다 | 네트워크 |
| `fx_on(fx, date, market)` | 해당 날짜 환율. 휴일이면 직전 영업일로 소급. `market=="KR"` 이면 1.0 | 순수 |
| `to_row(trade, fx_entry, fx_exit, capital, costs)` | 트레이드 1건을 원화 행으로 | 순수 |
| `build_rows(result, fx, capital, costs)` | 청산완료·미결·요약 세 덩어리 조립 | 순수 |
| `write_xlsx(path, closed, opened, summary)` | openpyxl 로 3시트 기록 | 파일 |
| `main()` | 조립과 CLI | - |

계산은 전부 `to_row` 한 곳에 있고 순수하다. 네트워크는 `fetch_fx` 하나뿐이다.

### 환산 규칙

```
원화진입가 = 진입가 × 진입일환율
수량       = floor(1,000만원 / 원화진입가)          # 0 이면 1 로 올린다
투자원금   = 원화진입가 × 수량
총수익(원) = 청산가 × 청산일환율 × 수량 − 투자원금
매수비용   = (매수요율 + 슬리피지) / 100 × 진입가 × 수량 × 진입일환율
매도비용   = (매도요율 + 세율 + 슬리피지) / 100 × 청산가 × 수량 × 청산일환율
순수익(원) = 총수익 − 매수비용 − 매도비용
총수익(%)  = 총수익 / 투자원금 × 100
순수익(%)  = 순수익 / 투자원금 × 100
```

- 수량이 0이 되는 경우(원화진입가 > 1,000만원)는 1주로 올린다. 현재 유니버스에
  그런 종목은 없으나, 0주는 손익 0이라 트레이드가 조용히 사라진다. 이때
  투자원금은 1,000만원을 넘지만 퍼센트는 여전히 정확하다.
- 두 퍼센트의 분모는 모두 투자원금이다. 순수익%의 분모에 매수비용을 더하지
  않는다 — 분모가 달라지면 두 컬럼을 나란히 비교할 수 없다.
- 한국 종목은 환율 1.0 이므로 분기 없이 같은 식을 탄다.
- 미결 포지션도 매도비용을 뺀다. 청산가 자리에 평가가격을 넣어 `cost_r` 을
  부르는 기존 시뮬레이터와 같은 처리다. 지금 팔면 남는 돈이 평가액이다.

### 기존 코드 수정 2건

**1. `trade_sim.cost_r` 에서 요율 분기를 분리한다.**

```python
def cost_amount(entry_price, exit_price, market, costs) -> tuple[float, float]:
    """왕복 비용을 (매수측, 매도측) 가격 단위로 돌려준다."""

def cost_r(entry_price, exit_price, r_unit, market, costs) -> float:
    buy_side, sell_side = cost_amount(entry_price, exit_price, market, costs)
    return (buy_side + sell_side) / r_unit
```

리포트가 요율 분기(미국/한국/세금)를 두 번째로 구현하면, 요율을 고칠 때 한쪽만
고치는 사고가 난다. `cost_r` 의 동작은 바뀌지 않는다.

**2. `Trade` 에 `mark_price: float` 를 추가한다.**

미결 포지션은 `exit_price=None` 이라 평가 가격이 밖으로 나오지 않는다.
`entry_price + gross_r × r_unit` 로 역산할 수는 있으나, 시트2 전체가 그
역산에 의존하는 건 취약하다. `_make_trade` 가 받는 `exit_price` 를 그대로
`mark_price` 에 넣는다. 청산완료 트레이드에서는 `exit_price` 와 같은 값이다.

## XLSX 구성

### 시트1 `청산완료`

| 열 | 컬럼 | 서식 |
|---|---|---|
| A | 상품티커 | 텍스트 |
| B | 진입일자 | `yyyy-mm-dd` |
| C | 진입가격 | `#,##0.00;-#,##0.00` |
| D | 청산일자 | `yyyy-mm-dd` |
| E | 청산가격 | `#,##0.00;-#,##0.00` |
| F | 총수익(원) | `#,##0;-#,##0` |
| G | 총수익(%) | `0.00"%";-0.00"%"` |
| H | 순수익(원) | `#,##0;-#,##0` |
| I | 순수익(%) | `0.00"%";-0.00"%"` |
| J | 수량 | `#,##0` |
| K | 진입환율 | `#,##0.00` |
| L | 청산환율 | `#,##0.00` |
| M | 청산사유 | 텍스트 |

정렬은 청산일자 오름차순, 동일 날짜는 티커 오름차순.

청산완료가 0건이어도 헤더 행만 있는 시트를 만든다. 시트가 없으면 파일이
깨진 것인지 트레이드가 없는 것인지 구분되지 않는다.

### 시트2 `미결포지션`

시트1과 같은 열 구성이되 D=`평가기준일`, E=`현재가`, L=`평가환율`,
M=`보유봉수`. 손익은 평가손익이다.

### 시트3 `요약`

라벨-값 2열. 위에서부터:

1. **경고 블록** — 데이터 오염·표본 부족 경고 (본문 "알 수 있는 것과 없는 것")
2. 리포트 생성일시 (KST), 아카이브 기간, `live`/`backfill` 행수
3. 청산완료 건수 · 승률 · 누적 총수익(원) · 누적 순수익(원) · 평균 순수익률(%)
   — 평균은 트레이드별 순수익률의 단순평균이다. 금액 가중이 아니다
4. 미결 건수 · 평가 순손익(원)
5. 가정 명시 — 정액 1,000만원, 정수 주 내림, 비용요율, 환율 출처

승률·평균은 청산완료만으로 계산한다.

### 음수 표기

모든 금액·퍼센트 셀에 `양수;음수` 2구획 커스텀 서식을 적용한다. 음수 구획에
`-` 를 명시하므로 회계 서식의 괄호 표기 `(636,000)` 는 나오지 않는다.
퍼센트는 값을 `12.34` 로 저장하고 서식으로 `%` 를 붙인다 — Excel 기본 `0.00%`
서식은 값이 `0.1234` 여야 해서, 셀을 직접 읽는 사람이 100배 틀린다.

## 실행

`.github/workflows/report.yml`

- `cron: '0 1 * * 1-5'` (UTC 01:00 = **KST 월~금 10:00**) + `workflow_dispatch`
- 스캔(22:00 UTC)이 끝난 3시간 뒤다. 그날 KST 07:00 스캔 결과가 이미 아카이브에 있다.
- 영업일은 **단순 월~금**이다. 한국·미국 공휴일은 구분하지 않는다. 휴일에는
  전일과 같은 내용의 리포트가 하나 더 쌓인다 — 거래소 캘린더 의존성을
  들이는 것보다 낫다.
- 파일명의 `YYYY-MM-DD` 는 리포트를 만든 **KST 날짜**다. 아카이브 최종일과
  다를 수 있다(스캔 실패로 그날 데이터가 없는 경우).
- artifact 이름은 `perf-report-<KST날짜>` 다. 같은 날 재실행하면 같은 이름의
  artifact 가 갱신된다.
- `if-no-files-found: error` 로 빈 업로드를 막는다. 리포트가 없는데 성공으로
  끝나면 며칠씩 비는 것을 눈치채지 못한다.
- 실패 시 이슈 자동 생성 — `scan.yml` 의 기존 패턴을 그대로 쓴다.

### 보존

artifact 는 90일 뒤 만료된다. 영구 보존이 필요하면 받아서 로컬에 두면 된다.
리포트 자체는 파생물이라 잃어도 복구된다 — 원천은 `history/*.csv` 이고,
`python perf_report.py` 가 같은 결과를 다시 만든다. 다만 **환율은 조회
시점 기준**이라, 아주 오래 지난 뒤 재생성하면 과거 환율 데이터 가용성에
따라 값이 미세하게 달라질 수 있다.

### 실패 처리

환율 조회에 실패하면 **리포트를 만들지 않고 실패**시킨다. 고정환율로 대체하면
조용히 틀린 금액이 리포에 커밋된다. 시세 조회 실패 종목은 `backtest.run()` 이
이미 `failed` 로 넘겨주므로 요약 시트에 적는다.

## 테스트

`tests/test_perf_report.py`

- `fx_on` — 정확 일치 / 휴일 소급 / 소급할 데이터가 없으면 예외 / 한국 종목 1.0
- 수량 내림, 원화진입가 > 정액이면 1주
- 원화 손익·퍼센트 — 환율이 변한 미국 종목, 환율 1.0인 한국 종목
- 비용 정합 — `to_row` 의 원화 비용을 `r_unit` 으로 나눈 값이 `cost_r` 과 일치
- `write_xlsx` 왕복 — 임시 파일에 쓰고 openpyxl 로 재독, 셀 값과 `number_format` 검증
- 음수 서식 회귀 — 손실 트레이드 셀의 서식 문자열에 `-` 구획이 있는지
- 미결 포지션이 시트1에 섞이지 않는지

`trade_sim` 수정분은 기존 테스트가 회귀를 잡는다. `cost_amount` 분리 후에도
`cost_r` 결과가 같아야 한다.
